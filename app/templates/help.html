How ImportGuard works, from first upload to final download.

Open workspace →

The import workflow

  1. Upload a CSV in the workspace. Files are profiled locally: headers, row counts, and sample values.
  2. Review the schema generated from your headers and adjust target fields.
  3. Map source columns to target fields. Deterministic matching proposes mappings first; optional AI assistance only suggests the unresolved ones and never runs your data.
  4. Validate and process. Every row is checked; accepted and rejected rows are reported separately.
  5. Review results, then export a corrected ZIP with accepted rows, rejected rows, a report, and a replayable recipe.

Guests and accounts

Guests can run the full workflow up to the download step. Downloads require an account: sign in and pending guest work is claimed automatically on the pending downloads page.

Saved exports expire after {{ retention_days }} days. Deleting your account removes everything immediately. See privacy and data handling for details.

Recipes and replay

Each export package includes a recipe file describing the schema and mappings. Re-run the same recipe against a new file from the workspace replay panel instead of mapping again.

Troubleshooting

  • Upload rejected? Check the file is a UTF-8 CSV within the size and row limits shown in the workspace.
  • Rows rejected? Open the rejected-rows file in the package; each row carries the reason it failed validation.
  • Download expired? Stored packages expire with the export record; re-run the import to produce a new file.
  • Locked out? Use password recovery. If email delivery is not configured on this server, contact the server operator.
